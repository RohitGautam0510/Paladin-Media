## 1. Objective & Hypothesis
* **Objective:** Evaluate lossless compression (zlib / DEFLATE Level 9) applied to plaintext secret media strictly **before** AES-256-GCM encryption and Reed-Solomon error correction, characterizing capacity amplification and boundary cases across heterogeneous media types.
* **Hypothesis:**
  1. Plaintext media containing statistical or spatial redundancy will achieve significant compression ratios ($2\times$ to $150\times$), allowing oversized media ($> 12\text{ KB}$) that would otherwise be rejected by the single-carrier hard gate ($8,176\text{ B}$) to fit easily.
  2. For already compressed formats (PNG) or maximum-entropy random byte streams, compression will yield slight expansion ($\approx 0.97\times$ to $0.99\times$) due to DEFLATE block header overhead.
  3. Compression applied before encryption preserves 100% bit-exact recovery and AES-GCM authentication.

---

## 2. Invariant & Pipeline Sequence
Per governing architectural constraints, compression is strictly positioned at the front of the sender pipeline:
```text
SECRET MEDIA -> LOSSLESS COMPRESS -> SERIALIZE -> AES-256-GCM -> REED-SOLOMON -> EMBED
```
**Cryptographic Rationale:** Ciphertext generated by AES-256-GCM possesses maximal Shannon entropy ($\approx 8.0\text{ bits/byte}$). Lossless compression applied after encryption is mathematically incapable of reducing size. Therefore, compression must occur before encryption.

## 4. Key Findings & Operating Strategy
1. **Capacity Breakthrough for Uncompressed Media:** Uncompressed graphic media (Fixture B, 12,288 bytes) and verbose structured payloads (Fixture C, 12,845 bytes) both exceed single-carrier capacity and fail the baseline hard gate. Compression before encryption compresses Fixture B by $149.85\times$ (down to 82 bytes) and Fixture C by $9.81\times$ (down to 1,309 bytes), allowing both to pass with zero carrier errors.
2. **Boundary Expansion Penalty:** For data already at maximum entropy (e.g. pre-compressed PNG or cryptographically random bytes), compression expands payload by 5 to 11 bytes.
3. **Adaptive Compression Recommendation:**
   Implement an adaptive heuristic in `SecretSerializer`:
   ```python
   compressed = zlib.compress(data, level=9)
   if len(compressed) < len(data):
       payload_data = compressed
       metadata["compressed"] = "zlib"
   else:
       payload_data = data  # Bypass compression
   ```
   This guarantees monotonicity: compression is applied when beneficial, and bypassed when it would cause expansion.
